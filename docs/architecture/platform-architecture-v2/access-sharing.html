Access & sharing

Granular RBAC as data: a founder invites someone with a role, a scope (down to a single workflow), and an optional expiry. Every request in the whole platform is checked against these grants. Adding a role is a row in a roles table, not a code change. (The founder-facing screen is mocked in v1; here's the system behind it.)

Storage note. Two small tables carry the whole model: roles (seed data — Founder, Team, Ops, Advisor, Lawyer/Accountant) and access_grants (company_id, principal, role, resource, scope, expires_at). PostgreSQL row-level security uses these same rows so the database itself enforces the boundary, not only the app. Shared deployment.
