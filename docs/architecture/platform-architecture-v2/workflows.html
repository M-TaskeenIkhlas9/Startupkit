Workflows W1–W8

One generic engine runs every workflow: an ordered set of phases, each with an actor (StartupKit / provider / founder) and a mode (automated / assisted / manual), gated by dependencies (depends_on / unlocks). But each workflow plugs different integrations and produces different artifacts — so the engine is shared and the edges differ. This page shows both: the engine six ways, then what makes each W-code distinct.

Part B · What differs per workflow

Same engine, different edges

Each workflow's "different system design requirements" live almost entirely in which external systems it touches and what it produces. Below, one conceptual diagram per W-code (its distinct integrations), plus a signature flow for the three most distinct.

W1 · Business Formation — the flagship, and the only one with an irreversible deadline

Incorporate, get an EIN, auto-derive the cap table & compliance calendar, and arm the 83(b) fuse. Touches the most government/provider systems.

W2 · IP & Legal

Document-generation heavy: IP assignment agreements, NDAs, and the DPA for EU customers — all grounded, validated, and e-signed.

W3 · Financial Infrastructure — custom Connect / Configure / Generate tracker

Integration-heavy: connect banking and payments, configure books/tax, then generate. Its UI replaces the generic phase tracker.

W4 · Tech & Infrastructure — largely declarative / planned

Domain, hosting, and core tooling setup. Lightest external footprint; mostly checklists and links today.

W5 · Brand & Product — AI-generation heavy, plus a production layer

Pick a positioning "play," generate a full brand core + visual system, chat to refine, and produce real assets (wordmark, favicon, a published site).

W6 · People & HR

Plan hiring roles, then generate offer letters and onboarding docs per employee, tracking onboarding + access state.

W7 · Go-To-Market — the most integration- and research-rich

Infer motion, research pricing & target accounts, rank channels, run sequences/campaigns, track a pipeline, and export to real tools. Reads the Brand Core as inherited context.

W8 · Operations & Tooling

Runs across the whole company object — the ongoing operating layer (tooling, cadences) rather than a one-time setup.

Storage note. Every workflow persists into the same two shapes in the one Postgres: structured progress and per-workflow blobs as JSONB (brand, people, gtm…), and generated/signed documents as bytea. Provider tokens (W3) get the encrypted-column treatment (see Input layer for the PII pattern). Shared deployment.
