StartupKit · Platform Architecture

Five diagrams, one system.

The same platform from index.html, redrawn through the five standard architecture-diagram types — conceptual, component, deployment, sequence, and data flow — each following its own drawing method so it answers the specific question it's built to answer.

1 · Conceptual Architecture Diagram

What is the system, and who does it talk to?

Purpose: a bird's-eye view for both technical and non-technical stakeholders — the core system, the external entities around it, and the interactions between them. No internals.
2 · Component Architecture Diagram

What are the internal pieces, and how do they talk?

Purpose: decompose the system into components, define their interfaces, and map the dependencies between them — the guide developers actually build against.
3 · Deployment Architecture Diagram

What actually runs where?

Purpose: map software components onto physical/cloud infrastructure — nodes, connections, and configuration (load balancing, replication, security groups).
4 · Sequence Diagram

Fill, sign, and submit — in order

Purpose: model one concrete interaction over time. Chosen here because it's the case that actually shaped §04's storage split: a template gets filled, downloaded, signed outside the platform, and the signed copy comes back.
5 · Data Flow Diagram (DFD)

Where does the data actually go?

Purpose: trace data itself — sources and destinations (rectangles), transforming processes (rounded shapes), and data stores (open rectangles) — independent of which service happens to run each process.
